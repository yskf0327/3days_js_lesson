## 目的

育成講師2名（出野先生・辻野先生）が、**求職者支援訓練における Web クラスで JS 授業を自分で組み立て・実践できる**ようになること。

**「わかる」と「理解」の区別（2026-08-24整理）**：8/19〜21 の3日間で TA として授業を聞いた状態は「わかる」（その場では納得できている状態）に留まっている可能性がある。8/25 研修で目指すのは「理解」（自分の言葉で受講生に説明し直せる、想定外の質問にも自分の理解に立ち戻って答えられる状態）。この差を埋めることが研修の主眼。

#### 研修内容の検討（たたき台）

質疑応答がメインになる想定だが、模擬授業の再現（付け焼き刃）だけでは突発的な突っ込んだ質問に対応できない懸念があるため、以下の3部構成を検討中。

1. **座学（JavaScriptの根本理解）**
   - 範囲は絞る：深いCS理論ではなく、教材（`docs/agenda.md`）で扱う概念の「裏側」を理解する程度
   - 例：`querySelector`が最初の1件だけ返す理由 / `addEventListener`と`onclick`の違い / `classList`操作と直接`style`操作の違い
   - 併せて、教材で意図的に「対象外」とした領域（イベント委譲、`aria-*`、配列からのHTML動的生成など。詳細は`docs/agenda.md`の「対象外」項目）についても、なぜ扱わないかを説明できる程度の理解を持たせる
2. **模擬授業の再現**
   - `docs/agenda.md`の3日間カリキュラムをなぞる形で進行練習
3. **オプションUIの解説・ライブコーディング**
   - 受講生からよく「実装したい」と言われるUI（例：アコーディオン、タブメニュー、スムーススクロール、トップへ戻るボタンなど）を、ドロワーと同じ「取得→クリック→classList」の型の応用として解説・実演
   - **位置づけの注意**：あくまで育成講師自身の引き出しであり、本課題（受講生向けカリキュラム）には組み込まない。`docs/agenda.md`で対象外とした方針と矛盾しないよう、その旨を明示して伝える

**トレードオフ**：座学（根本理解）に時間を割きすぎると、模擬授業の再現・質疑応答の時間が削られる。4時間という限られた時間の中で範囲を絞ることが前提。

### 2026-08-24（月）── 研修構成・時間配分の確定

**ゴールの再整理**：上記「目的」に追記した「わかる」と「理解」の区別を踏まえ、②模擬授業パートを「見せる」形式から「**出野先生・辻野先生自身に教えてもらう（ミニティーチング）→フィードバック**」形式に変更。TAとして聞いて納得した内容を、自分の言葉で説明し直せるかをその場で検証する。

**① 座学の内容確認（2026-08-24）**：`trainer_workshop_content.md`のA・B項目について過不足チェックを実施。モーダルの属性値コピー部分（②の最大の難所）に対応する裏側知識が抜けていたため、A-4「要素間のデータ受け渡し（クロージャ）」を新設（A項目は5→6項目に）。冒頭で出野先生・辻野先生がスコープ／クロージャの概念を知っているか前提確認を行い、知らない場合のみ簡単に補足する構成とした。なお、スコープ・クロージャは`docs/agenda.md`の1日目「変数の深い説明はしない」方針に合わせ、受講生への新規教材化はしない（育成講師向けの裏側知識に限定）。B-1（イベント委譲）は「モーダル実装のオプションとしてのイベントバブリング」というコード例を追加し、他のB項目より分量が増えた。

**優先順位の確認（2026-08-24）**：「トレーニーの基礎知識の充実」と「模擬講義」のどちらを優先すべきか検討した結果、**模擬授業（ミニティーチング＋問答）を優先**する方針とした。座学の内容は`trainer_workshop_content.md`として資料化済みで研修後も参照・自習できるが、「教えてみて理解の穴が露呈する」体験は研修当日にしかできず、「わかる→理解」というゴールに直結するため。トレードオフとして、座学が薄すぎるとミニティーチング②（モーダル）でのフィードバックが浅くなるリスクがあるため、**A-4（データ受け渡し／クロージャ）だけは死守して丁寧に扱い、他のA・B項目は資料参照ベースで軽く流す**割り切りとした。

**模擬授業の形式（2026-08-24更新）**：「トレーニーが一人で説明→まとめてフィードバック」ではなく、**短い説明（2〜3分）→トレーナー（私）が都度質問を挟む問答形式**に変更。理由：一人語りのままだと聞き手が受け身に戻り「わかる」に逆戻りするリスクがある。「なぜここでこう書くのか」「もし〇〇だったらどうなるか」と実際の受講生対応に近い形で問答することで、理解の深さをその場で検証する。

**ライブコーディングの追加（2026-08-24）**：口頭説明だけでは実演でしか出ない詰まり（セレクタのタイプミス等）を確認できないため、①②それぞれ自分の担当パートで**実際にコードを打ちながら教えてもらう**時間（3分）を追加。両講師とも少なくとも1回はライブコーディングを経験する形にした。時間は各パートの説明・問答を圧縮して吸収し、コマ全体の配分は変えていない。
